# Canonical terminology for Ephemeral Sandbox v1

Status: PW0 vocabulary record grounded in the source baseline `b22862550e0a7cb4fe61ce581831e9244cc492b5`, `project_inventory.md`, `claim_evidence_map.md`, `cli_contract_matrix.md`, and `paper_story.md`. Revalidate source-defined terms against the eventual annotated `paper-v1-freeze` tag.

| Canonical term | Precise paper definition | Source or claim-map basis | Unsafe synonyms or overclaims |
|---|---|---|---|
| **LayerStack** | The runtime's ordered, manifest-selected history of the base plus promoted published or squash layers from which workspace views are projected. | `project_inventory.md` Sections 1--2; C1, C2, D3, D7. | Not a general version-control system, database, or proof of immutable storage. |
| **layer** | A base, published, or squash filesystem contribution referenced in LayerStack order. Promoted layers are content-digested and treated as append-oriented/immutable by the runtime after promotion. | `project_inventory.md` Sections 1 and 5; C2, D7. | Avoid filesystem-enforced immutability, universal deduplication, or a Git commit. |
| **manifest** | A versioned record containing the schema version and ordered layer references; its derived root hash identifies that logical LayerStack view. | `project_inventory.md` Section 1; D3, D7. | Not a mutable working tree, process snapshot, or serializable database snapshot. |
| **active head** | The currently shared durable project view selected by the active manifest. Successful data publication advances this view through manifest replacement. | `project_inventory.md` Sections 4--5; C2, D5--D7. | Avoid Git branch head unless explicitly discussing a Git baseline; not live private session state. |
| **lease** | A runtime handle that captures one exact manifest and resolved ordered layer-path set, retaining those layers or a safe substitute until release. | `project_inventory.md` Section 2; C1, D3. | Not serializable snapshot isolation, a lock on all publication, or a cross-restart guarantee. |
| **workspace session** | A runtime-owned private executable workspace over a leased LayerStack view, with a unique writable overlay and namespace holder, that persists until its finalization or destruction path completes. | `project_inventory.md` Section 1; C1, C4, D1--D2. | Not a VM, a formal security boundary, or a process checkpoint. |
| **implicit session** | The workspace session automatically created for a sessionless `exec_command`; it uses `publish_then_destroy` after its command ledger drains and currently uses the shared-network profile. | C1, D1; `cli_contract_matrix.md` runtime-client section. | Do not say every tool call creates one: sessionless file operations follow different paths. |
| **explicit session** | A caller-created workspace session whose ID groups multiple command and file calls over one private live overlay until explicit publication or destruction. Precommit failure or rejection can preserve it for retry. | C1, C4, D2, D9; `cli_contract_matrix.md`. | Not automatically published per call; not a transaction spanning data, audit, and cleanup. |
| **private overlay** | The Linux OverlayFS projection with shared read-only lower layers and a session-unique upper/work pair in which uncommitted filesystem changes remain private. | `project_inventory.md` Section 1; C1, D2, D4. | Avoid complete noninterference, universal egress isolation, cross-platform support, or private process state after capture. |
| **capture** | Walking the private upper directory and interpreting OverlayFS metadata to produce typed filesystem changes and protected drops for publication planning. | `project_inventory.md` Section 3; C2, D4. | Not process-state capture, checkpointing, a generic recursive diff, or proof that every special file is publishable. |
| **candidate changeset** | The complete captured filesystem delta proposed by a session before it has been reconciled with the current active head. | C2; D4--D6; `paper_story.md` system stages. | Avoid accepted patch, durable layer, or semantically valid change. |
| **current-head reconciliation** | The publication step that re-reads the active manifest, compares candidate paths with leased-base and current-head fingerprints, applies eligible bounded text merge rules, and either resolves every change or rejects the data changeset. | `project_inventory.md` Section 4; C2, D5--D6. | Not semantic merge, serializable execution, arbitrary binary merge, or automatic test verification. |
| **publication** | The source-defined plan, reconciliation, staging, sync, promotion, and active-manifest transition that makes one accepted resolved data changeset durable and visible. Attribution, accounting, and cleanup occur outside this atomic data boundary. | `project_inventory.md` Sections 4--6; C2, C4, D6--D9. | Avoid Git merge/commit as an exact synonym, and avoid a transaction covering audit or cleanup. |
| **rejection** | A structured publication outcome in which an unresolved or prohibited change prevents the entire candidate data changeset from being published and leaves the active manifest unchanged. | C2, C4, D6; `paper_story.md`. | Not partial acceptance, semantic test failure, or necessarily session destruction. |
| **atomic data publication** | All-or-none visibility of one fully resolved data changeset through the implemented active-manifest replacement boundary after layer promotion. | C2; D6--D8; `project_inventory.md` Section 5. | Never shorten to unqualified atomic transaction; excludes attribution, accounting, cleanup, semantic correctness, and untested cross-platform crash guarantees. |
| **useful work** | Verification-passing, durably accepted contribution units measured per unit wall time or resource cost for a stated workload, runtime, agent configuration, and worker count. | M2; C5; `paper_story.md` problem gap. | Not attempts, generated tokens, merged lines, nominal parallelism, or agent productivity in general. |
| **concurrency ceiling** | The workload- and runtime-specific region in which adding workers no longer improves useful-work rate because conflict, retry, integration, verification, selection, or resource costs dominate marginal accepted progress. | M2--M5; C5; `paper_story.md`. | Not a universal agent-count threshold, a single-digit constant, or an assumed monotonic curve. |
| **agent team** | The structured evaluation workload family in which workers have relatively stable roles, delegated tasks, dependencies, handoffs, and an orchestrator or integration lane. | M0b; `paper_story.md` problem gap; `lanes/experiments.md` RQ4. | Not every multi-agent product or proof that coordination is centralized or effective. |
| **exploratory swarm** | The evaluation workload family in which many workers pursue redundant or competing work with weaker central coordination, hot-path overlap, rapidly changing bases, and result selection. | M0b; `paper_story.md` problem gap; `lanes/experiments.md` RQ4. | Not uncoordinated chaos, a universal product category, or evidence of higher concurrency by itself. |
| **workspace OS** | The bounded runtime substrate that provides LayerStack history, workspace-session execution, capture/publication, lifecycle, and operational observability for coding-agent work. | `paper_story.md` recommended title and claims-to-be-careful-about; C1--C4. | Not a general-purpose operating system, kernel, hypervisor, security monitor, or complete agent coordination plane. |

## Usage rules

- Qualify source-backed statements as baseline evidence until `paper-v1-freeze` exists.
- Use **atomic data publication** on first mention; define the active-manifest visibility boundary before using shorter wording.
- Use **implicit session** only for sessionless `exec_command`; explicitly qualify sessionless file-operation behavior.
- Use **agent team** and **exploratory swarm** as evaluation workload families, not universal taxonomies.
- Attach every measured use of **useful work** or **concurrency ceiling** to its workload, runtime, agent configuration, worker range, metric denominator, uncertainty, and frozen evidence.
